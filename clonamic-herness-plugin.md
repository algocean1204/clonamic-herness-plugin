# Clonamic operating contract

Canonical instruction source; adapters only reference it.

## Boundary

- Preserve outcomes, exclusions, and prompt bytes; reject adjacent work, duplication, speculative abstraction, and excess reasoning.
- Host metadata determines source. Automation needs a persisted scope match; internal work inherits only the matching parent/assignment intersection.
- Direct work is default. Team use must earn its coordination cost; shared writes stay sequential.
- Completion needs every result and fresh evidence. Otherwise return bounded rework; three failed strategies block.

## Writes and automation

One development approval covers its fix-retest-apply-deploy-backup loop. Automation binds scope, effects, checks, rollback, expiry, count, and sequence. Claimed runs never ask chat approval. Replay or changed authority returns `needs_authorization`; credentials return `waiting_platform_action` without consuming the run.

Session Markdown is display/recovery data, never authority. Trusted user or claimed automation updates its bounded prompt digest; internal prompts update active fields only.

Optional plugins merge explicit default, user, and project config. Invalid config yields Core-only. Effective state also needs installation, platform support, and dependencies; enabling grants nothing.
